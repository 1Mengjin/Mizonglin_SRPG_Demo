# 迷踪林单局时长归因：表现层固定等待审计

**证据**：`Artifacts/ForestRuns/forest-20261103-021856-778-cc1355.md` 与同名 `.csv`（872 笔事件）
**基线**：965.91 s（16:05）、23 回合、98 次主要行动、胜利
**代码快照**：`Assets/Scripts/Presentation/*.cs`、`Assets/Scripts/Combat/BattleDemo.Combat.cs`、`Assets/Scripts/Forest/*.cs`（行号对应当前工作区）

## 0. 一页结论

| 账目 | 秒数 | 占 965.91 s |
|---|---|---|
| **A. 表现层固定阻塞等待** | **216.3 s** | **22.4 %** |
| B. 玩家侧时间（决策 / 读盘 / 点击 / 教程弹窗） | 749.6 s | 77.6 % |
| 合计 | 965.91 s | 100 % |

- 每回合固定阻塞 **9.40 s**；每次主要行动固定阻塞 **2.21 s**；按全部 162 次 ActionEnd 摊算 **1.33 s/次**。
- 固定等待**不是主因**（22.4 %），但它是一笔"干净、可脚本化"的账：216.3 s 里有 **106.8 s（49 %）是每回合重复征收的税**（回合徽章 59.85 + 千面技能提示 46.98）。
- 真正的大头是 **749.6 s ÷ 98 次主要行动 = 7.65 s/次** 的玩家侧时间。
- 因此：**只压表现层最多把 965.91 s 压到 845 s（14 分钟），达不到 3–8 分钟**；必须叠加 task-2 的行动数削减。两者的联合测算见 §7。

## 1. 计费口径（先定规矩，再算账）

### 1.1 计时器本身

- 累计入口：`BattleDemo.Feedback.cs:28` → `ForestFeedback.Tick(...)`；`ForestFeedback.cs:13-16` 只在 `state.result == InProgress` 时累加 `Time.unscaledDeltaTime`。
- 只有 `Application.isFocused && !editing`（`BattleDemo.Feedback.cs:28`）才计时 → 965.91 s 是"窗口聚焦时的墙钟"，切出窗口不计。
- 胜利瞬间 `ForestFinishIfEnded()`（`BattleDemo.Forest.cs:174-183`）落盘并叫停计时，之后 `FinishBattle` 的结算面板（`BattleDemo.Combat.cs:126-156`）**不计入**。

### 1.2 「阻塞」的判定标准

只有同时满足"`busy == true` 或公告遮罩存在"与"玩家无法下达下一个指令"才算 A 账：

| 证据 | 位置 |
|---|---|
| 主循环在 busy 期间直接 return（不处理悬停/点击） | `BattleDemo.cs:346` |
| 点击入口拒绝 | `BattleDemo.cs:387`、`410`、`421`、`427` |
| 结束回合 / 重开按钮置灰 | `BattleDemo.cs:438-439` |
| 待机 / 取消 / 技能槽 / 元神按钮 / 战斗记录 / 悔棋 全部 `!busy` 门控 | `BattleDemo.Hud.cs:127,129`、`BattleDemo.Skills.cs:64`、`BattleDemo.Spirits.cs:69`、`BattleDemo.Feedback.cs:35-38` |
| 公告层整屏透明挡板 `raycastTarget = true` | `BattleDemo.Announcements.cs:24` |
| 教程弹窗期间主循环提前 return | `BattleDemo.cs:335-339` |

### 1.3 不计入的项（重要）

`StartCoroutine` 后不 `yield` 的表现都属于"并行"，玩家可继续操作，**一律不计**：

| 项目 | 位置 | 单次 | 说明 |
|---|---|---|---|
| 浮动战斗数字 | `BattleDemo.CombatVisuals.cs:176` | 1.15 s | `StartCoroutine(FloatCombatText)`（`CombatVisuals.cs:130-131`），不等待 |
| 受击抖动 / 死亡缩放 | `BattleDemo.CombatVisuals.cs:145` | 0.28 s | `StartCoroutine(AnimateHit)`（`CombatVisuals.cs:132`），不等待 |
| 唤灵 / 咒言光效 | `BattleDemo.BuffPulses.cs:59` | 0.46 s | `StartCoroutine(AnimateBuffPulse)`（`BuffPulses.cs:29`），不等待；但父协程会另等 0.50 s（见 A6） |
| 相机跟随缓动 | `BattleDemo.cs:367` | 每帧 | 非阻塞 |
| 敌方/我方血条追赶 | `BattleDemo.CombatVisuals.cs:74-75` | 每帧 | 非阻塞 |

### 1.4 回合口径

CSV 实测：`PlayerPhase` 23 次、`EnemyPhase` 22 次、`RoundEnd` 22 次 → 第 23 回合在**我方阶段胜利**，完整敌方阶段 22 轮。所以回合切换徽章是 `1（开场）+ 22×2 = 45` 次，不是 46 次。

## 4. 计算模型

### 4.1 主算式

```
A（固定阻塞）
 = A1 胜利条件横幅           4.72 × 1
 + A2 回合徽章               1.33 × 45
 + A3 我方技能横框           1.50 × 38
 + A4 敌方技能提示           1.74 × 27
 + A5 行动前摇               0.20 × 80
 + A6 打击停顿               0.50 × 19 + 0.32 × 48
 + A7 敌方移动               34 / 7
 + A8 奖励弹窗               2.00 × 1
 = 4.72 + 59.85 + 57.00 + 46.98 + 16.00 + 24.86 + 4.86 + 2.00
 = 216.27 s          （占 965.91 s 的 22.4 %）

B（玩家侧） = 965.91 − 216.27 = 749.64 s （77.6 %）
折合：每回合 749.64 / 23 = 32.59 s
      每次主要行动 749.64 / 98 = 7.65 s
```

### 4.2 两种"固定开销"的说法，别混用

| 口径 | 数值 | 含义 |
|---|---|---|
| 每回合固定 | **9.40 s/回合** | 216.27 / 23，含动作相关项摊到每回合的部分 |
| 每次主要行动固定 | **2.21 s/次** | 216.27 / 98 |
| 每次记录行动（含敌方空待机） | 1.33 s/次 | 216.27 / 162 |
| **真正的线性系数**（做方案预测时用这个） | — | 见下表 |

线性分解（近似，误差 < 1 %）：

| 缩放维度 | 系数 | 构成 |
|---|---|---|
| 每回合 | **4.65 s/回合** | 回合相关项 (59.85 + 46.98) ÷ 23；折成 22 个完整回合是 4.80 s/回合 |
| 每次我方主要行动 | **1.00 s/次** | (57.00 + 16.00 + 24.86) ÷ 98 |
| 每次敌方实质行动 | ≈ 0.95 s/次 | (46.98 + 30×0.20 + 10×0.32 + 4.86) ÷ 64 |
| 一次性 | ≈ 11.6 s | 开场横幅 4.72 + 奖励 2.00 + 敌方移动 4.86 |

> 校验：4.645 × 23 + 0.999 × 98 + 11.58 = 106.8 + 97.9 + 11.6 = 216.3 s ✓（回合税里已含开场那张徽章，勿重复计入）

### 4.3 A 账内部占比（决定先砍谁）

| 项目 | 秒 | 占 A 账 | 特性 |
|---|---|---|---|
| 回合徽章 | 59.85 | 27.7 % | **零信息量**，纯节奏填充 |
| 我方技能横框 | 57.00 | 26.4 % | 有信息（技能名/角色名），但 38 次里 14 次是每回合都点的展翼/疾行 |
| 敌方技能提示 | 46.98 | 21.7 % | 有信息（千面蓄力警告），但 27 次高度重复 |

## 5. 交叉校验与不确定性

| 事项 | 判断 | 可能偏差 |
|---|---|---|
| 965.91 s 无逐秒分布 | 只能做"次数 × 常量"，无法验证"每次都跑满常量" | 若某次按 Esc/右键跳过了公告，A 账会高估；但代码里公告层没有跳过分支（`BattleDemo.cs:344` 只是屏蔽输入，不中断协程），故不会缩短 |
| 教程弹窗 2 次（雾 / 千面） | 阻塞到玩家点"我知道了"（`Tutorials.cs:38`），时长不可测 | 按 15–35 s/次估计，约 30–70 s 落在 B 账里；这是一次性成本，磨平最划算 |
| 我方移动动画 | 224 格 ≈ 32 s，被 `Forest.cs:117` 转成阻塞的部分不可测 | 估 10–20 s；A 账真实值可能在 **216–236 s（22.4 %–24.4 %）** 区间 |
| 敌方移动速度取 7 格/秒 | `CombatVisuals.cs:94` 的 `* 7` 就是 7 世界单位/秒（格距 1 单位）；用 `unscaledDeltaTime`，掉帧不影响总时长 | 忽略不计 |

## 7. 与 task-2（行动数削减）的联合测算

假设 task-2 把 23 回合压到 12 回合、98 次主要行动压到 45 次（≈46 %），并按 §4.2 的线性系数缩放：
