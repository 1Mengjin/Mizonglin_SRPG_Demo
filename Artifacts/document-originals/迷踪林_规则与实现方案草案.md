# 迷踪林：规则、数据 Schema、关键结算与里程碑草案

本轮仅做设计梳理，未修改文件或代码。以下以[决策台账](决策台账.md)为规则和数值基准，[角色设计文档](角色设计文档.md)、[怪物设计文档](怪物设计文档.md)补充说明。文档中的“接入、测试”等表述作为需求资料，不视为本轮实施指令。

## ① 我理解的规则清单与歧义点

### 已明确的规则

| 类别 | 实现口径 |
|---|---|
| 地图与单位 | 左上角为 `(0,0)`；18×14，149 格可走，15 格初始雾；我方 4 人、敌方 7 个实例。 |
| 数据边界 | 模板保存固有属性与能力参数；生命、位置、瘴毒、蚀痕、冷却、携带物、姿态等全部保存在局内状态。重开重新创建状态。 |
| 回合 | 我方阶段 → 敌方按实例 ID 升序行动 → 回合末 → 回合数增加。上限 14 回合。 |
| 行动 | 一次移动机会后执行一次主要行动，也可原地行动或待机。普攻、符箓、治疗、涤尘、投掷、吞下共用主要行动；主要行动后不能再移动；移动路径不能穿过其他单位。 |
| 拾取 | 落地移动路径经过元神即自动拾取，不占主要行动，携带上限 1；允许本次行动内拾取后立即投掷或吞下。 |
| 伤害 | 有效攻击 `floor(基础攻击 × 形态倍率 × 瘴毒分子 / 10)`；无毒分子 10，有毒分子 7。伤害 `max(1,有效攻击−有效防御)`。只在最后取整。 |
| 反击 | 原防守方存活、具备攻击能力，双方当前普攻射程均为 1，且相邻，反击一次。反击不消耗行动、不继续引发反击。 |
| 瘴毒 | 仅作用于我方。回合末雾中 +1、干净格 −1，上限 3；先变层，再判掉血。1 层攻击 ×0.7；2 层另加移动 −1；3 层另掉 `ceil(有效最大生命/10)`。 |
| 地面雾 | 不阻路、不增加移动费用；与单位瘴毒分开。真正清除手段只有符箓、元神投掷、净行；吸雾属于污染转移。 |
| 符生 | 符箓射程 3，中心可选地图内任意格；清中心 3×3 内实际存在的可走雾格；全关一次，只清地面雾。 |
| 素铃 | 治疗与涤尘均为距离 2 单体、可选自身。治疗 30，无冷却、不复活；涤尘清普通瘴毒，N 回合使用，N+2 回合恢复，不清蚀痕和地面雾。 |
| 青羽 | 每次我方阶段开始选择一次姿态，当回合固定。飞行越障碍与单位、忽略根须额外费用，终点仍须可走且无其他单位；不能攻击、反击、拾取、投掷、吞下或净行。已有瘴毒减益与三层掉血保留，仅层数不变。 |
| 阿双 | 1–2 守、3–4 攻，四回合循环。守形态防御 36、不能攻击；攻形态攻击 90、防御 0、射程 2，自身每次行动结束且仍存活时自伤 7，含待机，最低留 1 血。 |
| 保护 | 仅守形态在我方阶段开始建立：相邻友方中当前生命比例最低者，同分按 C 编号。关系当回合固定；伤害按原目标防御计算，再整份转移，不再计算阿双防御；仅转移普攻和反击。 |
| 净行与蚀痕 | 每颗元神最多清 12 个雾格，仅落地移动生效、含起终点；第 4/8/12 格各加一层蚀痕。每层最大生命和当前生命各减 10，最低 1；不可驱散。百分比以削减后的最大生命为基数，自伤 7 除外。 |
| 树精 | 首爆在第 6 回合末，此后第 9、12 回合末。果级初始 1，受到一次主动攻击后 +1，上限 3；爆果后归 1。爆果按果级作为曼哈顿半径铺雾，不直接伤血。死亡立即取消爆果。 |
| 根须 | A 存活时（存活即蓄力，不存在非蓄力时段），进入 `(9,1)`、`(9,2)` 各耗 2 移动力，敌我通用；飞行除外。 |
| 吞噬怪 | 从 `(15,6)` 沿四点固定巡逻，目标被占则等待且不推进索引。回合末半径 2 吸最多 6 格，按距离、y、x 排序。死亡按同样排序向全图泄雾，未铺出的携雾不得丢失。 |
| 千面 | 4 阶段，每阶段 120 血；阶段归零立即掉一颗元神并转换，溢伤不跨阶段。每个敌方阶段攻击距离 2 内最近目标，同距按 C 编号。 |
| 腐卒 | 按含根须费用、不可穿越其他单位的合法路径，算到「目标攻击格」的最低成本追击；同成本按 C 编号、坐标 y→x；移动后相邻则攻击。 |
| 回合末顺序 | 树精 A → 树精 B → 吞噬怪吸雾 → 我方瘴毒变层 → 三层掉血 → 胜负检查。 |
| 死亡与评价 | 生命 ≤0 移除占位，携带元神落在死亡格；濒死线为 `max(1,floor(有效最大生命/5))`，曾经濒死须留历史标记；**死亡即便从满血被一击击杀，也按经历过濒死处理，「全程无濒死」评价失败**。 |
| 胜负 | 同一检查点满足“两树死亡、地面雾零、全部携雾零”才胜利，不要求击败千面和腐卒。行动后、回合末检查；敌方每次行动后也立即检查我方全灭。第 14 回合末先判胜利，再判超时；**同一检查点既全灭又达成清雾时，全灭失败优先**。 |
| 本期范围 | 不结算属相克制；不接焦土、三级果聚雾；吞噬怪增长关闭。 |

### 需要补充确认的边界

下列为 v1.0 文档未覆盖的边界。其中 D01、D02、D05、D06、D09 已回写进台账与两份设计文档，成为定案；D03、D04、D07、D08、D10 保留为实现口径。伪代码以这些口径为前提。

| 编号 | 歧义或冲突 | 建议口径 |
|---|---|---|
| D01 ✅已回写 | “同距上→右→下→左”不能完整排列距离 2、3 的全部掉落格。 | 每一距离圈从正上格 `(0,−d)` 起顺时针遍历整圈（先向右上斜边，经正右、正下、正左）。 |
| D02 ✅已回写 | 千面距离 1–3 内全部被占时，没有合法掉落格；已有元神能否共格也未规定。 | **每格最多 1 颗元神，不允许共格**，掉落只取「可走、无单位且无元神」的格，以消除"先拾哪颗"的歧义；仍无合法格则记录待掉落，行动后重试，不吞资源、不擅自扩大半径。1–3 圈约 20 个可走格、全场仅 11 个单位，该分支实际不可达，只作兜底。 |
| D03 | 净行未耗尽时再次吞下，是覆盖、叠加还是禁止？ | 按元神来源排队，各自独立记录 12 格额度及 4 格代价，不覆盖旧额度。 |
| D04 | 吞下时是否立即清脚下雾？原地待机是否触发净行？ | 吞下、待机不触发；下次实际移动时，从起点开始处理净行。 |
| D05 ✅已回写 | 泄雾的“可走空格”是无雾，还是也要求无单位？ | 指可走且无雾，允许生成在单位脚下，与爆果保持一致。 |
| D06 ✅已回写 | 地面单位能否穿过友方？腐卒如何计算到被占目标格的距离？ | 地面单位不能穿过其他单位；腐卒计算到目标合法相邻攻击格的最低路径成本。路径同价按固定上、右、下、左展开。 |
| D07 | 现有项目支持取消移动预览，但拾取、净行、蚀痕会改变状态。 | 预览只改副本；确认主要行动或待机时，整次行动一次提交。取消不留下拾取、清雾、蚀痕或次数消耗。 |
| D08 | 手动结束阶段跳过阿双时，是否规避自伤？ | 未行动者按实例 ID 顺序补原地待机，自伤照常，随后进入敌方阶段。 |
| D09 ✅已回写 | 同一检查点既全灭又满足清雾目标，谁优先？瞬间从健康被击杀是否影响“全程无濒死”？ | 全灭失败优先；胜利优先于超时。任意死亡也使“全程无濒死”评价失败；回合末状态伤害按统一批次处理。 |
| D10 | 第一回合青羽默认姿态未规定。 | 初始落地；每次阶段开始允许选择，确认后锁定；不更改则沿用当前姿态。 |

## ② 数据 schema 草案：模板字段与运行状态字段

采用关卡配置、单位模板、局内状态三层，不引入通用技能编辑器。

### 配置与模板

| 对象 | 字段草案 |
|---|---|
| `ScenarioDefinition` | `schemaVersion`、`scenarioId`、`rulesetId`、`map`、`unitTemplates[]`、`spawns[]`、`rules` |
| `MapDefinition` | `width/height`、`coordinateOrigin=TopLeft`、`terrain[]`、`regions[]`、`initialFog[]`、`rootCells[]`、`patrolPoints[]` |
| `SpawnDefinition` | `instanceId`、`templateId`、`cell`；出生格放这里，不写进模板 |
| `UnitTemplate` | `templateId`、`name`、`faction`、`profession`、`portrait`、`element`、`maxHp`、`attack`、`defense`、`move`、`basicRange`、`hasBasicAttack`、`behaviorKind`、专用参数 |
| `BattleRules` | 回合上限 14；瘴毒上限 3、攻击分子 7、分母 10、减移动 1、掉血 10%；濒死 20%；元神携带上限 1、投掷距离 4、半径 2；净行每颗 12 格、每 4 格加蚀痕、每层减生命 10 |
| 符生参数 | `castRange=3`、`squareSize=3`、`maxUses=1` |
| 素铃参数 | `healRange=2`、`healAmount=30`、`cleanseRange=2`、`cleanseCooldownTurns=2` |
| 青羽参数 | 姿态允许的移动、攻击、资源操作和净行能力 |
| 阿双参数 | `cycle=4`、`guardTurns=2`、`guardDefense=36`、`attackMultiplier=2`、`attackDefense=0`、`attackRange=2`、`selfDamagePercent=5` |
| 树精参数 | `firstBurstRound=6`、`burstInterval=3`、`maxFruitLevel=3`；A 的根须绑定关系放实例配置 |
| 吞噬怪参数 | `absorbRadius=2`、`absorbLimit=6`、`growthEnabled=false`、保留阈值 8 与上限 3；巡逻路径引用地图配置 |
| 千面参数 | `phaseCount=4`、`phaseHp=120`、`dropSearchRadius=3` |
| 腐卒参数 | 追击策略与固定排序规则，无额外技能 |

`hasBasicAttack=false` 明确表示没有攻击动作。树精、吞噬怪的攻击、射程可存 0，不能依靠“最低伤害 1”让它们获得攻击能力。

| M02 吞噬怪·暗 | 100 / 无 / 8 / 1 / 无 | M02-1 `(15,6)` |

### 局内状态

| 对象 | 字段草案 |
|---|---|
| `BattleState` | `round`、`phase`、`result`、`revision`、`unitsById`、`groundFog`、`spiritsById`、`pendingDrops[]`、`eventLog[]`、评价与统计 |
| `UnitState` | `instanceId`、`templateId`、`cell`、`currentHp`、`lifeState`、`acted`、`poisonStacks`、`scarStacks`、`carriedSpiritId`、`abilityStates` |
| 技能状态 | 符箓 `remainingUses`；涤尘 `availableRound`，剩余 CD 由当前回合推导 |
| 青羽状态 | `stance=Grounded/Flying`、`stanceLockedRound` |
| 阿双状态 | `form=Guard/Attack`、`protectedUnitId`、`protectionRound` |
| 净行状态 | `charges[]:{sourceSpiritId, clearedCount}`，每颗 0–12，按获得顺序消耗；对应 D03 |
| 树精状态 | `fruitLevel`、`nextBurstRound`；不另存"蓄力中"——存活即蓄力，根须条件因此等价于"A 存活" |
| 吞噬怪状态 | `nextPatrolIndex`、`carriedFogCount`；死亡后仍保留携雾残余记录 |
| 千面状态 | `phaseIndex`、`resolvedPhaseMask`，用于保证每阶段掉落一次 |
| `SpiritState` | `spiritId`、`sourcePhase`、`locationKind=Ground/Carried/Consumed/Pending`、`cell或carrierId`、`consumedBy` |
| `PreviewState` | `baseRevision`、`actorId`、`path[]`、`projectedState`、`predictedEvents[]`；不写入正式战斗状态 |
| 评价与记录 | `everNearDeath`、`everAllyDied`、各雾源击杀回合、每人行动/伤害/清雾统计、实际时长 |

以下值**实时推导，不重复保存为可写状态**：

- 有效最大生命、攻击、防御、移动、射程、可攻击性。
- 濒死线、瘴毒掉血量、剩余 CD、距形态切换回合数。
- 地面雾总数、携雾总数、存活雾源数。

关键约束：

- `有效最大生命 = max(1,模板最大生命−10×蚀痕层数)`。
- 死亡仅移除棋盘占位，不删除必要的携雾、掉落、评价记录。
- 污染记账满足：  
  `地面雾 + 全部携雾 = 初始雾 + 爆果实际新增雾 − 真正清除雾`。  
  吸雾、泄雾不算清除，也不算新增。
- 新旧规则由 `rulesetId` 区分；地图格式版本不承担规则版本职责。

## ③ 8 段关键结算伪代码

以下仅描述流程，不是待写入项目的代码。编号与补充口径 D01–D10 对应。

### 1．阶段开始、敌方调度与手动结束

```text
我方阶段开始：
    清除上回合保护关系；存活我方 acted = false
    阿双形态 = ((round - 1) mod 4 < 2) ? 守 : 攻
    若阿双存活且为守：
        候选 = 相邻存活友方
        按 当前生命/有效最大生命、C编号 排序，保护第一名
        比例比较使用交叉相乘，避免浮点同分误差
    开放青羽本回合姿态选择；确认后锁定
    技能可用性按 round >= availableRound 判断

手动结束我方阶段：
    未行动我方按ID顺序提交“原地待机”
    每次提交后若战斗结束则停止
    进入敌方阶段

敌方阶段，存活敌人按ID升序：
    树精：跳过主动行动
    吞噬怪：下一巡逻格空闲才移动并推进索引，否则等待
    千面：按 曼哈顿距离、C编号 选择射程内目标
    腐卒：以加权寻路比较到各目标合法攻击格的最低成本
          按 成本、C编号、落点y、落点x 决定目标和路径
          沿路径移动不超过预算，移动后相邻则攻击
    每次行动完成后执行胜负检查
全部完成后执行回合末结算
```

### 2．有效属性、直接伤害、保护与反击

```text
有效属性(unit)：
    maxHp = max(1, 模板maxHp - 10 × scarStacks)
    attack = floor(模板attack × 形态倍率 × (有毒 ? 7 : 10) / 10)
    move = max(0, 模板move - (poisonStacks >= 2 ? 1 : 0))
    defense、range、canAttack 按模板及当前姿态/形态推导

直接命中(attacker, 原目标, 类型)：
    damage = max(1, 有效攻击(attacker) - 有效防御(原目标))
    承伤者 = 原目标
    若类型为普攻或反击，且原目标有有效保护：
        承伤者 = 阿双
    扣除承伤者生命；更新濒死/死亡历史
    若生命归零：立即执行死亡或阶段转换
    不再按承伤者防御计算第二次

普攻交换(attacker, defender)：
    验证存活、敌对、攻击能力和射程
    直接命中(attacker, defender, 普攻)
    若本次主动攻击目标是仍存活树精：果级+1，上限3
    若原defender仍存活且可攻击、attacker仍存活，
       双方有效射程均为1且相邻：
        直接命中(defender, attacker, 反击)
    反击不递归触发反击、不催熟
```

### 3．移动预览与整次行动提交

```text
预览移动(command)：
    从正式状态复制试算状态
    验证路径邻接、预算、通行、终点与占位
    地面使用含根须费用的加权寻路；飞行每步费用1
    若确实移动：
        按 起点→各路径格 顺序：
            落地时处理净行
            落地、未携带且该格有元神时拾取一颗
            更新试算位置
    返回试算状态；正式位置、资源和事件记录不变

确认行动(command)：
    若预览版本过期，重新试算
    在副本完成移动，再验证主要行动
    执行普攻，或执行技能/元神操作，或待机
    若行动者是仍存活的攻形态阿双：
        currentHp = max(1, currentHp - ceil(模板maxHp × 5 / 100))
        更新濒死历史
    标记已行动；重试待掉落；执行胜负检查
    全部合法才一次提交副本与事件；失败不提交
取消预览：丢弃副本
```

### 4．死亡、千面转阶段与掉落

```text
处理生命归零(unit)：
    若是千面，且当前阶段尚未结算：
        标记本阶段已结算
        创建唯一元神：ID由千面实例ID与阶段号确定
        在距离1、2、3各圈按D01顺序找「可走、无单位且无元神」格（每格最多 1 颗元神）
        找到则落地，否则进入待掉落队列
        若不是最后阶段：
            phaseIndex += 1；currentHp = 阶段最大生命
            返回，不移除千面，不继承溢伤

    若是树精：取消爆果；若为A，根须费用立即失效
    若是吞噬怪：
        遍历全图可走无雾格，按 距离、y、x 排序
        每铺一格，carriedFogCount -= 1
        放不下的数量保留，记录“泄雾溢出”
    若携带元神：元神移到死亡格
    清除净行与关联保护；移除棋盘占位，保留历史记录
    若是我方：记录死亡，并使“全程无濒死”评价失败
```

### 5．主要技能与元神使用

```text
执行主要行动(actor, action)：
    符箓：
        验证剩余次数、曼哈顿距离<=3、中心在地图内
        清中心3×3内可走格上的实际雾；次数-1
    治疗：
        验证存活友方、距离<=2，可选自身
        生命恢复min(30, 有效最大生命-当前生命)
    涤尘：
        验证存活友方、距离<=2、round>=availableRound
        仅poisonStacks归零；availableRound = round+2
    投掷：
        验证携带元神、允许资源操作、距离<=4
        落点可走且无其他单位；不判视线
        清落点曼哈顿半径2内可走格上的雾；消耗元神
    吞下：
        验证携带元神、允许资源操作
        加入一份clearedCount=0的净行额度；消耗元神
        不立即清脚下雾
    所有清雾只统计实际删除的雾格
    不额外清单位瘴毒、蚀痕，不附带伤害
```

### 6．净行逐格清雾与蚀痕

```text
处理净行经过格(actor, cell)：
    若飞行、没有净行额度或该格无雾：返回
    取队首元神额度
    清除此格雾；clearedCount += 1；记录真正清除1格

    若clearedCount为4、8、12：
        scarStacks += 1
        newMax = max(1, 模板maxHp - 10 × scarStacks)
        currentHp = min(newMax, max(1, currentHp - 10))
        立即更新濒死历史，后续治疗不抹除此历史

    若clearedCount == 12：
        移除该份额度
    后续路径只能使用剩余额度
    同一已清格再次经过不扣额度；若后来重新有雾则可再次清除
```

### 7．回合末：爆果、吸雾、瘴毒

```text
回合末：
    存活树精按A、B顺序：
        若round == nextBurstRound：
            在曼哈顿半径fruitLevel内的可走格铺雾，允许单位脚下
            只记录原来无雾的新增格
            fruitLevel = 1；nextBurstRound += 3

    存活吞噬怪按实例ID顺序：
        半径2内雾格按 距离、y、x 排序，取前6格
        从地面删除这些雾；carriedFogCount增加同等数量
        记录为转移，不记录为清除

    对所有存活我方先计算本次新层数：
        飞行青羽保持原层数
        其余：有雾+1，无雾-1，限制在0..3
    再为新层数为3者计算ceil(有效最大生命/10)掉血
    批次应用掉血，更新濒死记录并立即处理死亡
    状态掉血不经过保护，不触发反击

    执行回合末胜负检查
    若仍进行中：round += 1，进入下一我方阶段
```

### 8．检查点、胜负与守恒核对

```text
胜负检查(checkpoint)：
    核对地面雾与所有携雾记录，包括死亡吞噬怪残余：
        地面雾 + 携雾 = 初始雾 + 爆果实际新增 - 真正清除
    核对元神：
        每个已击败阶段对应且仅对应一颗元神记录
        元神只能处于地面、携带、已消耗、待掉落之一

    若存活我方数量为0：
        失败：全灭
    否则若两棵树均死亡 且 地面雾为0 且 全部携雾为0：
        胜利
    否则若checkpoint为回合末 且 round>=14：
        失败：超时
    否则继续

    胜负只在完整行动后或完整回合末判断
    不在吸雾、阶段转换、反击之间提前宣布胜利
    守恒不符作为验证错误报告，不用清空记录来“修正”
```
